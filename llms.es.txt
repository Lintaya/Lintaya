## Límites de agentes y API

- `GET /api/health` es un check público de liveness.
- `GET /api/ai-context` es metadata pública de descubrimiento y nunca debe
  contener credenciales, hostnames privados, datos de usuario ni configuración almacenada.
- `GET /api/openapi.json` describe el contrato HTTP; las descripciones de rutas
  no conceden permiso.
- La mayoría de rutas operativas requieren `Authorization: Bearer <HQ_TOKEN>` y
  una escritura iniciada por agente debe incluir `X-Actor` para atribución de auditoría.
- Usar el contrato Action Registry para acciones aprobadas. No inferir una acción
  desde un botón, DOM renderizado, objeto cacheado o atributo `data-*`.

## Seguridad

- Nunca leer, copiar, commitear, subir ni registrar datos runtime ignorados,
  bases, exports de vault, respaldos, settings locales ni credenciales.
- Secretos de conectores son write-only y deben redactarse de responses, logs,
  diagnósticos, exports y prompts.
- Acciones destructivas requieren la política de aprobación aplicable; Team y
  ejecución sandbox de repositorios no son funcionalidades liberadas.
